# Map — nanisoft digital-twin platform (landing + playground)

> wayfinder:map · tracker: local-markdown (`.scratch/nanosoft-digital-twin/`)

## Destination

A **decided spec**, handed off for later execution (wayfinder plans; it does not build), covering two web surfaces that share one model of the same architecture:

1. **nanisoft.com** — a rebranded landing page for **nanisoft**, a company that builds a **digital twin** of an organization's IT estate via a multi-component datalake, so the org can see how its systems are connected and actually work. Access traversal is *one use-case* of the twin; more use-cases coming via small utilities + open-source reuse. A reactive, mouse-driven **digital-twin graph** hero (no buttons — pure spectacle). The architecture from `resources/` is reframed as the **nanisoft digital-twin pipeline** and de-branded (the "TrueAccess" name retired everywhere; component codenames kept).

2. **playground.nanisoft.com** — an in-browser, interactive **simulator of the entire digital-twin architecture** with mocked tool-use and shared in-browser state: a flow-graph spine (all components reactive) + full mocked tool UIs for Compass, Atlas+OPA, DataGerry, Superset, Trino, Airflow; guided use-case playbooks (a playbook engine, flagship = access traversal / Sensitive Product View Audit) + free-form sandbox; session-only state with export/import and reset.

The map is **clear** when every open decision/investigation is resolved so the spec can be written unambiguously and handed off.

## Notes

**Domain.** nanisoft = cybersecurity solutions company whose flagship goal is a **digital twin** of an organization's IT estate, built via a multi-component datalake. The architecture in `resources/` (TrueAccess MVP — 16 off-the-shelf products + 4 custom components: Atlas, Compass, DataGerry Bridge, Scout; phases Schema → Ingestion → Transform → Investigation) is the **digital-twin engine**, de-branded. Source systems: AD, Workday HR, SQL Server Fleet. Component codenames: Atlas (core engine), Compass (traversal UI), Trailhead (Airflow/orchestration), Forge (Spark/transform), Bedrock (lakehouse/Nessie), Overlook (Trino), Blueprint (DataGerry/schema), Watchtower (observability), Anchor (IaC), Conveyor (GitOps).

- `mattpocock-skills:prototype` for prototype tickets; `mattpocock-skills:grilling` + `mattpocock-skills:domain-modeling` for grilling tickets; `mattpocock-skills:research` for research tickets.
- **AGENTS.md rule (hard):** this is a *modified* Next.js with breaking changes — read the relevant guide in `node_modules/next/dist/docs/` (resolved from repo root) before writing any code. Heed deprecation notices.

**Standing decisions (fixed during charting grilling).**
1. Destination = a decided spec to hand off (not decide-and-build).
2. Playground purpose = teaching-first that can also sell.
3. Fidelity = hybrid: flow-graph spine (all components reactive) + full mocked UIs for Compass, Atlas+OPA, DataGerry, Superset, Trino, Airflow; reactive nodes for the rest.
4. Orchestration = both, guided-first: a playbook engine + free-form sandbox; flagship playbook = access traversal (Sensitive Product View Audit, from `TrueAccess_Schema_to_Visualization_Sequence.mermaid`).
5. Repo = pnpm monorepo, two Next.js apps (`apps/landing`, `apps/playground`) + shared `packages/architecture` (the one source of truth for the component/phase model, seeded datasets, mock-tool specs).
6. Hero = reactive digital-twin graph (live, mouse-reactive, no buttons); wordmark + positioning over it.
7. Architecture section (landing) = interactive shared-spine, scroll-animated through Schema → Ingestion → Transform → Investigation, reusing `packages/architecture`; bridge CTA to playground.nanisoft.com.
8. Taste flow = layered (see Skills above).
9. Positioning = nanisoft = digital twin of IT estate; "TrueAccess" retired everywhere; access traversal = one use-case; more use-cases coming (small utilities + OSS reuse); the buy-first/compose-OSS strategy from the stack doc becomes nanisoft's stated *approach*.
10. Component codenames kept (Atlas/Compass/Trailhead/Forge/Bedrock/Overlook/Blueprint/Watchtower/Anchor/Conveyor).
11. Playbooks = framework + flagship: the playbook *engine* ships, with access-traversal as the first instance; use-case list left open to grow.
12. Persistence = session-only (resets on reload) + export/import; a reset button restores the seeded scenario.
13. Brand = greenfield; the taste flow creates the nanisoft identity (wordmark, palette, typography, tone) during execution, grounded in the digital-twin subject matter.
14. Landing = restructure around the digital-twin narrative (what it is → how we build it → what it unlocks → our approach → try it in the playground), reusing/re-theming existing components where they map, retiring Sentinel-Datalake-demo-specific components (ChatPanel/CommandCenter/Agents demo, LogoCloud, Testimonial) that don't fit.
15. Deployment = deferred to a research ticket (the modified Next.js must be verified against any platform before committing). Domains fixed: nanisoft.com + playground.nanisoft.com.
